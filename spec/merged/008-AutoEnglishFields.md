Safari와 Firefox에서 한글을 입력할 수 없는 필드(숫자, 암호)를 알아내서 자동으로 영문으로 입력되게 하려고 해.

# 사용자의 요청
- safari나 firefox에서 한글을 입력할 수 없는 text 필드를 인식해서 해당 필드에서는 자동으로 영문으로 입력할 수 있도록 할 수 있는지 확인
  1. 숫자만 입력하는 필드
  2. 암호 입력 필드

# 현재 파악된 상태
- 확인 환경: macOS 26.7.3, Safari 27.2, Firefox 159.0.1, 설치된 입력기 0.1.2. 브라우저 소스는 2026-11-17 기준 WebKit, Firefox의 main
- 직접 확인 (2026-11-17): 테스트 페이지의 스크립트가 2초마다 필드 포커스를 옮기고, 손쉬운 사용 권한이 있는 도구가 포커스 변경 알림과 입력 소스를 기록함. 암호 필드에서는 도구가 Shift+Space와 `k`를 보냄. macOS의 "문서의 입력 소스로 자동 전환"은 꺼진 상태(기본값)
- STANDARD에는 필드에 따라 모드를 바꾸는 규칙이 없음. 모드는 Shift+Space로 바뀌거나, 시스템이 바꾸면 따라감 (§3)
- 한글 모드에서 숫자 줄 키는 자모를 넣음 (`1` → 종성 ㅎ, `4` → 중성 ㅛ 등). 숫자는 Shift+`y` `u` `i` `o` `p` `h` `j` `k` `l` `;` (§4.1)
- 입력기가 앱에서 받는 정보에는 필드 종류가 없음
  - IMKTextInput(macOS 26 SDK): 번들 ID, 글자와 범위, 글자 위치, 창 레벨 정도. 필드 종류를 알려 주는 메서드는 없음
  - AppKit에는 iOS의 keyboardType 같은 것이 없음 (NSTextInputTraits는 자동 고침 같은 설정뿐)
  - 앱은 쓸 수 있는 입력 소스를 ASCII 호환으로 제한할 수 있음 (TSM 문서 속성 `kTSMDocumentEnabledInputSourcesPropertyTag`, AppKit `allowedInputSourceLocales`). 그러면 macOS가 입력 소스를 바꿈
- 소스: 입력기는 앱의 번들 ID만 확인함 (§3 Ghostty, §4.5 터미널). 손쉬운 사용 권한은 키를 다시 보낼 때(§4.5)만 씀

## 암호 필드
- §7.4 L2: 암호 필드에서는 macOS가 ASCII 호환 입력 소스만 허용해서 한글 모드를 쓸 수 없음. 한계로만 적혀 있음
- 브라우저는 암호 필드에 포커스가 가면 보안 입력(`EnableSecureEventInput`)을 켜고 ASCII 호환 입력 소스만 허용함
  - Safari: `allowedInputSourceLocales`를 Roman 입력 소스로 제한 (WebKit `WebViewImpl::updateSecureInputState`)
  - Firefox: `TISCreateASCIICapableInputSourceList()`로 제한 (`nsCocoaWindow::SetInputContext`). 암호 필드에서도 키를 입력기에 보냄
  - Chrome도 Firefox와 같은 방식 (`ui/base/cocoa/secure_password_input.mm`)
- 이 Mac의 입력 소스
  - English 모드는 ASCII 호환, 한글 모드는 아님 (`kTISPropertyInputSourceIsASCIICapable`). §3에도 English 모드는 ASCII 호환이라고 있음
  - 켜져 있는 ASCII 호환 입력 소스: ABC, skon's Keyboard English
  - 가장 최근에 쓴 ASCII 호환 입력 소스: skon's Keyboard English
- 직접 확인한 결과 (Safari, Firefox 같음)
  - 한글 모드에서 암호 필드로 가면 macOS가 English 모드로 바꾸고, 입력기는 따름 (§3). ABC가 아님. 가장 최근에 쓴 ASCII 호환 입력 소스가 English 모드였음. ABC를 더 최근에 썼을 때는 확인하지 않음
  - 필드를 떠나도 한글 모드로 돌아오지 않음. 다른 필드에서도 English 모드 그대로
  - 암호 필드에서 Shift+Space를 누르면 입력기가 한글 모드를 요청하고, macOS가 받아 줌 (메뉴 막대 "한")
    - Firefox: 이어서 친 `k`가 `ㄱ`으로 암호에 들어감
    - Safari: 아무것도 들어가지 않음. WebKit은 암호 필드에서 ASCII 한 글자가 아닌 조합은 버리고 경고음을 냄 (`WebViewImpl::setMarkedText`)

## 숫자 필드
- 브라우저는 숫자 필드를 입력기에 알려 주지 않음
  - Safari: 입력 소스를 제한하는 것은 암호 필드뿐
  - Firefox: 숫자 필드도 보통 텍스트 필드와 같음. 웹 페이지가 CSS `ime-mode`(Firefox만 지원, 비표준)를 쓸 때만 다름. `ime-mode: inactive`면 포커스가 갈 때 가장 최근의 ASCII 호환 입력 소스로 바꾸고, `disabled`면 암호 필드처럼 제한함
- 손쉬운 사용 API로는 포커스된 필드를 일부 구분할 수 있음 (아래 표는 직접 확인과 같음)

| 필드 | Safari | Firefox |
|---|---|---|
| `type="password"` | AXTextField, 서브롤 AXSecureTextField | AXTextField, 서브롤 AXSecureTextField |
| `type="number"` | AXTextField. 안에 증감 버튼(AXIncrementor)이 있음 | AXIncrementor |
| `type="tel"`, `inputmode="numeric"` 등 | AXTextField (보통 텍스트 필드와 같음) | AXTextField (같음) |

- 손쉬운 사용 API를 쓰려면
  - 손쉬운 사용 권한이 있어야 함. 지금 이 권한은 선택 사항이고 §4.5에만 씀 (§2.2)
  - Firefox는 다른 프로그램이 손쉬운 사용으로 물어보면 접근성 기능을 켬. 켜진 동안 Firefox가 접근성 정보를 계속 만들어서 부담이 늘어남
  - 웹 페이지 안에서 포커스가 옮겨 갈 때 입력기가 받는 신호가 브라우저마다 다름. 숫자 필드에 들어가고 떠나는 것을 모두 알려면 손쉬운 사용의 포커스 변경 알림을 받거나, 키를 누를 때마다 확인해야 함
    - Safari: 웹 화면 전체가 입력 컨텍스트 하나라서 필드끼리 옮길 때는 신호가 없음. 편집할 수 없는 곳(페이지 바탕, 다른 페이지)으로 가면 입력 컨텍스트를 없애서(nil) 비활성화(`deactivateServer`)를 받을 것으로 보임 (WebKit `WebViewImpl::inputContext`)
    - Firefox: 편집할 수 있는 필드로 포커스가 가면 비활성화 뒤 활성화(`deactivateServer`, `activateServer`)를 흉내 내서 보냄. 편집할 수 없는 곳으로 가면 신호가 없음 (`IMEInputHandler::NotifyIMEOfFocusChangeInGecko`)
    - 다른 앱이나 창으로 옮기면 두 브라우저 모두 비활성화를 받음 (지금도 이때 조합을 확정함)
    - 포커스 변경 알림(`AXFocusedUIElementChanged`)은 두 브라우저 모두 웹 페이지 안의 포커스가 바뀔 때 보냄 (WebKit `AXObjectCacheMac.mm`, Firefox `mozAccessible.mm`)
      - 직접 확인: 두 브라우저 모두 브라우저 앱에 등록한 알림으로 옴. 필드끼리 옮길 때와 페이지 바탕으로 갈 때(AXWebArea) 모두. Safari는 웹 페이지를 다른 프로세스(WebContent)가 그리는데, 그 알림도 옴
      - 필드가 아닌 요소의 알림이 섞여 옴. Firefox는 필드에 들어갈 때마다 바로 뒤에 창(AXWindow), Safari는 암호 필드에 들어갈 때 웹 화면 그룹(AXGroup). 알림의 요소만 보고 필드를 떠났다고 판단하면 안 됨
      - Safari에서 새로 연 탭의 첫 포커스는 필드 알림 없이 웹 화면 그룹(AXGroup) 알림만 옴. 그다음 포커스부터 필드 알림이 옴
  - §2.4는 입력이 없을 때 타이머, 폴링, 백그라운드 스레드를 금지함. 포커스 변경 알림은 타이머나 폴링이 아님

## 가능 여부
- 암호 필드: 입력기가 필드를 알아내지 않아도 브라우저와 macOS가 English 모드로 바꿈 (직접 확인). 부족한 부분은 떠날 때 한글 모드로 돌아오지 않는 것과 Shift+Space (논의사항 1, 2)
- 숫자 필드: 손쉬운 사용 권한이 있을 때 `type="number"`만 알아낼 수 있음. 들어가고 떠나는 것은 포커스 변경 알림으로 알 수 있음 (직접 확인). `type="tel"`이나 `inputmode="numeric"`으로 만든 숫자 필드는 알아낼 방법이 없음

# 명세서 수정 방향
- 필드에 따른 자동 영문 전환 규칙 추가 (§3 또는 새 절)
  - 암호 필드: macOS가 ASCII 호환 입력 소스만 허용하면 시스템이 고른 입력 소스를 따름. Safari, Firefox에서 손쉬운 사용 권한이 있을 때, 떠나면 들어가기 직전 모드로 돌리고, 안에서 Shift+Space는 소비만 함 (논의사항 1, 2)
  - 숫자 필드: Safari, Firefox에서 손쉬운 사용 권한이 있을 때, 포커스가 `type="number"` 필드로 가면 English 모드로 바꾸고 떠나면 들어가기 직전 모드로 돌림. 안에서 Shift+Space는 소비만 함 (논의사항 3–5, 8, 9)
- §1.2: 범위 표에 추가
- §2.2: 손쉬운 사용 권한의 용도에 숫자 필드와 암호 필드 인식 추가. 권한이 없어도 타이핑은 그대로
- §7.3: 인수 시나리오 추가 (Safari, Firefox)
  - 한글 모드에서 암호 필드에 `abc` 입력 → `abc`. 필드를 떠나면 한글 모드 (권한이 있을 때)
  - 한글 모드에서 숫자 필드에 `123` 입력 → `123`. 필드를 떠나면 한글 모드 (권한이 있을 때)
  - 숫자 필드나 암호 필드에서 Shift+Space를 누르고 `abc` 입력 → `abc`. English 모드 유지 (권한이 있을 때)
- §7.4 L2: 확인 결과대로 고쳐 씀. 자동 전환되지 않는 숫자 필드(`type="tel"`, `inputmode="numeric"` 등)를 한계로 추가
- §8.2: 설치 화면의 손쉬운 사용 항목이 숫자 필드와 암호 필드 인식에도 쓰인다는 내용

# 논의사항
1. 암호 필드를 Safari와 Firefox에서 직접 확인
   - 확인할 것: 선택되는 입력 소스(English 모드, ABC), 필드를 떠날 때 한글 모드로 돌아오는지, Shift+Space
   - ABC가 선택되면 영문은 입력되지만 메뉴 막대는 ABC 아이콘이고, Shift+Space는 공백으로 들어감
   - 확인함: English 모드가 선택됨. 떠나도 한글 모드로 돌아오지 않음. Shift+Space를 누르면 한글 모드가 됨 (현재 파악된 상태)
   - 문제: 떠날 때 한글 모드로 돌아오지 않음. 고치려면 숫자 필드처럼 손쉬운 사용으로 암호 필드를 떠나는 것을 알아야 함
   - 제안: 권한이 있을 때 숫자 필드와 같은 방식(8)으로 돌림. 권한이 없으면 지금처럼 English 모드로 남음 (§7.4에 적음)
   - 결정: 제안대로
2. 암호 필드에서 Shift+Space
   - 소비만 하고 English 모드를 유지: 암호에 한글이 들어가지 않음
   - 지금처럼 한글 모드로 전환: 확인해 보니 Firefox는 암호에 한글이 들어가고, Safari는 아무것도 들어가지 않음 (WebKit은 경고음을 냄)
   - 암호 필드인지는 손쉬운 사용으로 알아냄 (서브롤 AXSecureTextField). 권한이 없으면 지금처럼 바뀜
   - 제안: 소비만 하고 English 모드를 유지 (9와 같은 방식)
   - 결정: 제안대로
3. 숫자 필드의 범위
   - 알아낼 수 있는 것은 `type="number"`뿐
   - 전화번호, 인증번호처럼 `type="tel"`이나 `inputmode="numeric"`으로 만든 필드는 자동 전환이 안 됨
   - 질문: 불편했던 숫자 필드가 어떤 것이었는지
   - 결정: 알아낼 수 있는 `type="number"`만 함. 나머지는 §7.4에 한계로
4. 숫자 필드를 손쉬운 사용 권한으로 알아낼지
   - 함: 권한이 있을 때만 동작 (§4.5처럼 선택 사항). Firefox의 접근성 기능이 켜짐
   - 안 함: 숫자 필드는 지금처럼 Shift+Space로 바꿈. §7.4에 한계로 적음
   - 제안: 3의 답을 보고 정함. 불편했던 필드가 `type="number"`가 아니면 안 함
   - 결정: 함. 권한이 있을 때만 동작
5. 숫자 필드에서 바꾸는 방식 (4에서 하기로 하면)
   - 시스템 입력 소스를 English 모드로 바꿈 (메뉴 막대 "A"). 필드를 떠나면 원래 모드로
   - 입력 소스는 그대로 두고 그 필드에서만 키를 넘김 (메뉴 막대는 "한"인데 영문이 들어감)
   - 제안: 시스템 입력 소스를 바꿈. 암호 필드와 같은 모습이고 메뉴 막대가 늘 현재 모드를 보여 줌 (§3). 포커스 변경 알림으로 바꿈
   - 결정: 제안대로
6. 대상 앱
   - 요청대로 Safari, Firefox
   - 암호 필드는 macOS가 처리해서 Chrome도 결과가 같음. 숫자 필드는 앱마다 확인이 필요함
   - 제안: 숫자 필드는 Safari, Firefox만
   - 결정: 제안대로
7. 버전: 지금 Cargo.toml은 0.1.3이고 아직 릴리즈 전 (마지막 태그 v0.1.1). 올릴지
   - 제안: 0.1.3 그대로. 다음 릴리즈(develop → main)에 005, 007과 같이 나감
   - 결정: 0.1.4로 올림
8. 숫자 필드를 떠날 때 원래 모드로 돌아가는지
   - 질문: 숫자 필드에서 영문으로 자동으로 바뀐 뒤, 마우스로 포커싱을 바꿔서 벗어나거나 엔터를 쳐서 입력을 완료하는 등의 동작이 있으면 원래의 입력으로 돌아갈 수 있는지. 한글이었으면 한글, 영문이었으면 영문 그대로
   - 답: 가능 (손쉬운 사용 권한이 있을 때). 숫자 필드에 들어가기 직전의 모드를 기억해 두고, 포커스가 숫자 필드가 아닌 곳으로 가면 그 모드로 돌림. 영문이었으면 들어갈 때 바꾸지 않았으므로 그대로 영문
   - 마우스로 다른 필드나 페이지 바탕을 누르거나 Tab을 누름: 포커스 변경 알림으로 돌림
   - 엔터: 폼이 제출돼 페이지가 바뀌거나 웹 페이지가 포커스를 옮기면 돌림. 커서가 그 필드에 남아 있으면 영문 유지. 엔터만 보고 돌리면 이어서 숫자를 칠 때 자모가 들어감
   - 숫자 필드에서 다른 숫자 필드로 가면 English 모드 유지. 기억한 모드도 그대로
   - 다른 앱이나 창으로 가면 돌림. 다시 그 필드로 오면 English 모드
   - 필드 안에서 입력 메뉴로 모드를 바꾸면(§3) 기억한 모드를 버리고, 떠날 때 바꾸지 않음
   - 숫자 필드와 암호 필드 사이를 옮길 때: 암호 필드도 English 모드라서 같은 종류로 봄. 둘 다 아닌 곳으로 갈 때 돌림 (1에서 암호 필드도 돌리기로 하면)
   - 제안: 위와 같이 포커스를 기준으로 돌림. 포커스 변경 알림은 두 브라우저 모두 옴 (직접 확인)
   - 결정: 제안대로
9. 숫자 필드 안에서 Shift+Space
   - 질문: 숫자 필드 안에서 일단 영문이 되었으면, 거기 안에서 Shift+Space를 해도 그대로 영문을 유지할 수 있는지
   - 답: 가능. 알아낸 숫자 필드 안에서는 Shift+Space를 소비만 하고 모드를 바꾸지 않음 (2의 첫째 안과 같은 방식)
   - 다른 안: 지금처럼 한글 모드로 전환하고, 그 필드에 있는 동안은 한글 모드 유지 (5에 있던 안)
   - 입력 메뉴나 macOS 단축키로 바꾸는 것은 막을 수 없음. 입력기는 시스템이 바꾼 모드를 따름 (§3)
   - 알아내지 못하는 숫자 필드(`type="tel"`, `inputmode="numeric"` 등)에서는 지금처럼 바뀜
   - 제안: 영문 유지. 그러면 숫자 필드 안에서는 늘 English 모드이고, 떠날 때 돌아갈 모드는 들어가기 직전의 모드 하나뿐임
   - 결정: 영문 유지
